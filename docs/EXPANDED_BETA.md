# Expanded beta: agent continuity, model library and attachments

8 November 2026. Owner requests a95/100-quality candidate, stronger agent context like GrokBot/dots, multi/all-model setup, photos/camera/files, tested beta and parallel App Store preparation. A score must follow independent evidence, not be manufactured. Build10 predates these capabilities.

## Implementation and boundaries

- Providers save a bounded selected model library (up to500 IDs), Select all returned models, and a default; chat uses a searchable focused picker and stores one active model per conversation. No parallel paid inference. Existing single-model connections migrate without losing keys. Catalog presence does not establish modality/tool capability; discovery may return only a provider page.
- Attach up to4 selected files, 2MB each/4MB combined: JPEG/PNG photos re-encoded toJPEG, optional still camera, PDF and readable TXT/Markdown/CSV/JSON. Text max100,000characters. No audio/video, Office/archives, background import or arbitrary filesystem access. iOS system pickers, optional camera permission, no microphone/broad-photo permission. Draft/file content persists inline in local SQLite and readable backups; keys remain excluded. Re-encoding removes original image EXIF; visible pixels and document content can still identify people.
- Responses carries input_image/input_file, Claude Messages image/document, ChatCompletions images/text with local PDF rejection. Each attachment-bearing send/retry asks named-provider permission including retained attachment history. Picking uploads nothing. Max8MB binary context and80k text request bounds; no separate persistent provider-file upload. Actual provider/model support requires live evidence.
- Agents have a current goal and direct/plan/coach working approach. Approved memories are durable; useful memory proposals always require approval. Optional recent-chat context retrieves bounded text from up to8 same-agent conversations (12kchars), omits current/other-agent/personal chats and incomplete outputs. Review/off controls explain that deleting memory does not erase sourcechat mentions. Imported backups cannot enable recent-chat sharing. Provider-sharing consent migrates to revision3 so old approval cannot silently authorize the new scope.
- Report response previews a minimal email report; excerpt optional, no other messages/files/keys. Nothing is delivered until the user sends in their email app. Local removal is available. Safety instructions apply to all custom roles/files; they are not a guarantee of filtering or provider behavior. See app-store-readiness.md for current Apple1.2/5.1.2 requirements and gaps.
- Previous maxtext fixes: empty chats scroll to top rather than end, accessibility-size empty state starts at top; memory actions stack below text at large scaling. Native verification required.
